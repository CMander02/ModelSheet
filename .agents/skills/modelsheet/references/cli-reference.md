# ModelSheet CLI Reference

Run commands from the repository root unless a section changes directories.

## Setup and Discovery

```powershell
uv sync
uv pip install -e .
uv run modelsheet --help
uv run modelsheet <command> --help
```

The Python distribution is `modelsheet`. The import package is `modelsheet_cli`, mapped to `src/modelsheet-cli`, and the entry point is `modelsheet_cli.cli:app`.

## Model Commands

```powershell
# Add one or more public repositories
uv run modelsheet model add Qwen/Qwen2.5-7B
uv run modelsheet model add Qwen/Qwen2.5-7B mistralai/Mistral-7B-v0.3

# Add IDs from a text or YAML file
uv run modelsheet model add --file models.txt

# Re-fetch all existing models; use only for an intentional broad refresh
uv run modelsheet model add --update-all

# Inspect local records
uv run modelsheet model list
uv run modelsheet model show Qwen/Qwen2.5-7B

# Remove only when explicitly requested
uv run modelsheet model remove Qwen/Qwen2.5-7B
```

The top-level `modelsheet add` alias may also be available. Prefer the explicit `modelsheet model add` form in reusable instructions.

## Scanning and Watchlists

```powershell
uv run modelsheet scan
uv run modelsheet scan --source hf
uv run modelsheet scan --source ms
uv run modelsheet scan --source hf --org Qwen
uv run modelsheet scan --watchlist
uv run modelsheet scan --show-skipped

# Save the reviewed snapshot
uv run modelsheet scan --commit

# Save and ingest discovered candidates
uv run modelsheet scan --commit --add

uv run modelsheet watchlist --help
```

`data/scan_snapshot.json` stores the reviewed baseline. `data/filter-suffixes.yaml` controls name-based scan exclusions.

## Filter Commands

```powershell
uv run modelsheet filter list
uv run modelsheet filter test Qwen/Qwen3-8B
uv run modelsheet filter add --pattern "pattern" --reason "reason"
uv run modelsheet filter remove --index 3
```

Treat filter changes as catalog policy changes. Test representative accepted and rejected IDs after editing a rule.

## Paper and Metadata Commands

```powershell
uv run modelsheet paper arxiv "DeepSeek-V3"
uv run modelsheet paper update org/model
uv run modelsheet tag openness open-weight org/model
uv run modelsheet tag list open-weight
```

Inspect subcommand help before using optional or provider-specific flags.

## Closed-Model Fetching

```powershell
uv run modelsheet fetch openai --help
uv run modelsheet fetch anthropic --help
uv run modelsheet fetch google --help
```

These commands use Playwright. Start with the dry-run option exposed by the selected subcommand, inspect the scraped JSON, and write only reviewed entries.

## Database Build and Verification

```powershell
uv run modelsheet db build
uv run modelsheet db seed
uv run modelsheet db verify
```

Expected artifacts:

- `data/modelsheet.sqlite`: ignored local build artifact.
- `data/d1/seed.sql`: committed, reviewable generated snapshot.
- `data/d1/seed.remote.sql`: ignored transaction-free remote import file.

## Frontend Build

```powershell
Set-Location src/modelsheet-web
npm ci
npm run build
```

Use `npm install` only when intentionally changing dependencies. Preserve the lockfile generated by the repository package manager.

## Local Pages and D1 Smoke Test

```powershell
Set-Location src/modelsheet-web
npm run build
npm run d1:migrate:local
npm run d1:seed:local
npm run pages:dev -- --port 8788
```

Open `http://localhost:8788`. The D1 binding already lives in `wrangler.toml`.

## Remote D1 Publishing

Run only when remote publication is explicitly requested and Cloudflare authentication is available.

```powershell
uv run modelsheet db build
uv run modelsheet db seed
uv run modelsheet db verify

Set-Location src/modelsheet-web
npm ci
npx wrangler d1 migrations apply modelsheet --remote
npm run d1:seed:remote
npx wrangler d1 execute modelsheet --remote --command "SELECT COUNT(*) AS model_count FROM models" --json
```

## Troubleshooting Checklist

1. Run the exact failing command with `--help` and confirm its current syntax.
2. Confirm the virtual environment and editable package are current with `uv sync` and `uv pip install -e .`.
3. Inspect `git status` and the partial data diff before retrying.
4. Query the model’s official API endpoint and repository files directly.
5. Check provider region, organization aliases, and ModelScope mappings in `data/providers.json`.
6. Check `data/filter-suffixes.yaml` when scanning omits a repository.
7. Inspect `data/temp/{org}/{model}/` for downloaded configs when ingestion reached the fetch stage.
8. Trace the pipeline in this order: `fetcher.py` -> `parser.py` and `extractors/` -> `exporter.py` -> `data/models.json`.
9. Test a single representative model after a code fix.
10. Rebuild and verify the database before reviewing the final diff.

Only one CLI process should write `data/models.json` at a time.
